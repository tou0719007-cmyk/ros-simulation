# ROS Topic 通信模拟系统——需求文档

## 项目背景

本项目是一个使用 C++ 实现的 ROS Topic 通信模拟系统。项目不依赖真实 ROS API，而是在标准 C++ 环境下模拟 ROS 中 Topic 发布订阅通信的基本机制。

在实际 ROS 系统中，Publisher 和 Subscriber 通常通过 ROS 中间件完成消息通信。本项目则使用标准 C++ 的面向对象、多线程、智能指针和容器机制，实现一个简化版的通信系统，用于展示 Topic 发布订阅模型、节点管理和异步消息处理的基本思想。

## 项目目标

本项目需要实现一个可运行的 C++ 程序，完成以下目标：

- 模拟 Publisher 向指定 Topic 发布消息。
- 模拟 Subscriber 订阅指定 Topic 并接收消息。
- 支持多个 Publisher 发布到同一个 Topic。
- 支持多个 Subscriber 订阅同一个 Topic。
- 由 `ROSCore` 统一管理节点、Topic 和消息转发。
- `Subscriber` 使用独立工作线程异步处理消息。
- 使用消息队列、互斥锁和条件变量保证线程安全。
- 使用 `std::shared_ptr` 和 `std::weak_ptr` 管理对象生命周期。
- 支持节点初始化、注册、注销和统一关闭。
- 对消息内容、节点名称等关键输入做基本异常检查。

## 功能需求

### 1. 消息功能

系统需要实现 `Message` 类，用于封装消息内容和时间戳。

- 消息内容不能为空。
- 消息创建时自动生成时间戳。
- 消息内容和时间戳只能通过接口读取。
- 消息接口返回 `const std::string&`，避免不必要的字符串复制。

### 2. 节点抽象

系统需要实现 `Node` 抽象基类，作为所有节点的公共接口。

- 每个节点都有唯一名称。
- 节点名称不能为空。
- 节点必须实现 `init()` 和 `shutdown()` 两个接口。
- 节点必须支持通过 `std::shared_ptr` 管理。
- 节点需要支持 `shared_from_this()`，便于向 `ROSCore` 注册。

### 3. Publisher 功能

`Publisher` 需要继承 `Node`，并实现消息发布功能。

- 每个 `Publisher` 绑定一个 Topic。
- Topic 名称不能为空。
- 初始化时向 `ROSCore` 注册。
- 发布消息时创建 `Message` 对象。
- 未初始化时不能发布消息。
- 关闭时从 `ROSCore` 注销。
- 析构时自动调用关闭逻辑。

### 4. Subscriber 功能

`Subscriber` 需要继承 `Node`，并实现消息接收和异步处理功能。

- 每个 `Subscriber` 订阅一个 Topic。
- Topic 名称不能为空。
- 初始化时向 `ROSCore` 注册。
- 初始化时启动独立工作线程。
- 接收消息时先进入消息队列。
- 工作线程从队列中取出消息并处理。
- 使用 `std::mutex` 保护共享消息队列。
- 使用 `std::condition_variable` 实现等待和通知。
- 使用 `std::optional<Message>` 暂存从队列取出的消息。
- 关闭时停止工作线程并等待线程退出。

### 5. ROSCore 功能

`ROSCore` 需要负责统一管理系统中的节点和 Topic。

- 采用单例模式。
- 管理 `Publisher` 和 `Subscriber` 的注册。
- 管理 Topic 与节点之间的映射关系。
- 根据 Topic 将消息转发给对应 `Subscriber`。
- 支持节点注销。
- 支持统一关闭所有活动节点。
- 使用 `std::weak_ptr` 避免长期持有节点对象。
- 避免在持有全局互斥锁时直接调用节点关闭函数。

### 6. 程序入口功能

`main.cpp` 需要实现一个可运行的通信演示程序。

- 创建多个 `Publisher`。
- 创建多个 `Subscriber`。
- 初始化所有节点。
- 发布多条消息。
- 等待异步消息处理完成。
- 调用 `ROSCore::shutdownAll()` 统一关闭节点。
- 在异常情况下输出错误信息并安全关闭系统。

## 非功能需求

- 程序必须能在 Windows 环境下使用 MinGW-w64 编译运行。
- 项目必须使用 C++17 标准。
- 项目不使用 CMake。
- 项目不调用真实 ROS API。
- 项目不引入第三方测试框架。
- 多线程逻辑必须保证基本线程安全。
- 对象生命周期必须能通过智能指针管理。
- 关键异常场景必须能被捕获并给出可读输出。
- 程序正常结束时，所有工作线程必须退出。

## 项目范围

本项目范围内包含：

- `Message` 类
- `Node` 类
- `Publisher` 类
- `Subscriber` 类
- `ROSCore` 类
- `main.cpp` 演示程序
- 基础异常检查
- 基础多线程通信机制

本项目范围内不包含：

- 真实 ROS API 调用
- QoS 策略
- 动态 Topic 发现
- 消息序列化
- 跨进程通信
- 分布式节点管理
- 复杂 QoS 或重传机制

## 项目限制

- 只使用标准 C++ 实现，不依赖真实 ROS。
- 编译环境为 MinGW-w64，不使用 CMake。
- 必须保留 C++17 特性，特别是 `std::optional`。
- 不改变现有类接口和文件结构。
- 不为了文档生成而修改业务代码。
- 不把尚未实现的功能描述为已实现。

## 验收标准

- 项目能够编译通过。
- `main.exe` 能够正常运行。
- 多个 Publisher 和 Subscriber 能够完成基本通信。
- 同一 Topic 下多个 Subscriber 能收到消息。
- 不同 Topic 之间保持隔离。
- `Subscriber` 能使用独立工作线程异步处理消息。
- 程序关闭时工作线程能正常退出。
- 关键异常场景不会导致程序意外终止。
- 文档内容与当前源码实现保持一致。
