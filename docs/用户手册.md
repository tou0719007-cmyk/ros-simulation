# ROS Topic 通信模拟系统——用户手册

## 软件简介

本程序是一个基于 C++17 的 ROS Topic 通信模拟系统。程序不调用真实 ROS API，而是在普通 C++ 环境中模拟多个发布者和订阅者之间的 Topic 消息通信。

运行程序后，可以看到：

- 创建 2 个发布者和 2 个订阅者；
- 节点初始化并注册；
- 发布者发布 3 条消息；
- 订阅者通过独立工作线程接收并输出消息；
- 所有节点统一关闭，程序正常结束。

## 运行环境

### 软件要求

- 操作系统：Windows。
- 编译器：MinGW-w64 的 g++（支持 C++17）。
- 开发工具：Visual Studio Code（可选）。

### 编译器要求

项目使用 C++17 标准，编译器必须支持：

- `std::thread`（多线程）
- `std::mutex`、`std::condition_variable`、`std::atomic`（线程同步）
- `std::shared_ptr`、`std::weak_ptr`（智能指针）
- `std::optional`（C++17）

MinGW-w64 g++ 8.1 及以上版本即可满足要求，编译时必须加上 `-std=c++17` 参数。

## 项目目录说明

项目文件都位于同一个目录（例如 `C:\Users\hao17\Desktop\Ros`）：

| 文件 | 作用 |
| --- | --- |
| main.cpp | 程序入口 |
| Message.h / Message.cpp | 消息数据管理 |
| Node.h / Node.cpp | 节点抽象基类 |
| Publisher.h / Publisher.cpp | 发布者实现 |
| Subscriber.h / Subscriber.cpp | 订阅者实现 |
| ROSCore.h / ROSCore.cpp | 核心管理与消息转发 |
| tests/test_ros_sim.cpp | 功能测试程序（可选） |
| docs/ | 项目文档 |

`main.exe`、`tests/test_ros_sim.exe` 是编译生成的可执行文件，不需要手工维护。

## 编译步骤

### 第一步：进入项目目录

打开 PowerShell，执行：

```powershell
cd C:\Users\hao17\Desktop\Ros
```

### 第二步：编译主程序

执行：

```powershell
g++ -std=c++17 -pthread *.cpp -o main.exe
```

编译成功后会生成 `main.exe`。

参数说明：

| 参数 | 作用 |
| --- | --- |
| -std=c++17 | 启用 C++17 标准（项目使用了 `std::optional`，缺少该参数会报错） |
| -pthread | 启用多线程支持 |
| *.cpp | 编译当前目录下的 C++ 源文件 |
| -o main.exe | 指定生成的可执行文件名称 |

如果编译出错，请根据错误提示检查：

- 是否所有源码文件都在同一目录。
- 是否使用了支持 C++17 的编译器。
- 是否缺少 `-std=c++17` 参数（典型错误：`expected primary-expression before '>' token`，即 `std::optional` 不被识别）。

### 第三步（可选）：编译测试程序

```powershell
g++ -std=c++17 -Wall -Wextra -g tests\test_ros_sim.cpp Message.cpp Node.cpp Publisher.cpp Subscriber.cpp ROSCore.cpp -o tests\test_ros_sim.exe
```

## 运行步骤

编译成功后，在 PowerShell 中执行：

```powershell
.\main.exe
```

运行测试程序：

```powershell
.\tests\test_ros_sim.exe
```

## 正常运行流程

程序启动后会自动执行以下流程，无需手动操作：

1. 创建 2 个发布者（`publisher1`、`publisher2`）和 2 个订阅者（`subscriber1`、`subscriber2`），都使用 Topic `/chatter`。
2. 初始化各节点，订阅者启动工作线程。
3. 发布者依次发布 3 条消息：`Hello ROS!`、`C++ Topic Communication`、`第二条消息`。
4. 两个订阅者通过各自的工作线程接收并输出消息。
5. 等待 1 秒后，统一关闭所有节点，程序结束。

## 错误提示说明

| 错误信息 | 含义 |
| --- | --- |
| 消息内容不能为空 | 发布了空字符串消息 |
| 节点名称不能为空 | 创建节点时名称为空 |
| Topic 名称不能为空 | 创建发布者或订阅者时 Topic 为空 |
| 发布者尚未初始化 | 没有调用 init() 就调用 publish() |
| 节点名称重复: xxx | 两个节点使用了相同名称 |

主程序捕获到异常后会输出 `[ERROR] ...`，并调用统一关闭接口后退出。

## 常见问题

### 编译时提示 `expected primary-expression before '>' token`

原因是编译命令中没有加 `-std=c++17`，`std::optional` 是 C++17 类型。请确认使用：

```powershell
g++ -std=c++17 -pthread *.cpp -o main.exe
```

### 控制台中文显示乱码

程序已调用 `chcp 65001` 设置 UTF-8 代码页。如果仍乱码，请确认终端本身支持 UTF-8，或运行前手动执行 `chcp 65001`。

### 编译找不到 g++

说明 MinGW-w64 没有加入系统 PATH。可以打开其 `bin` 目录下的 `g++.exe` 执行，或在 PowerShell 中把 g++ 所在目录加入 PATH。

### 第一次运行出现 `std::invalid_argument` 异常、第二次运行正常

历史原因：旧编译产物仍包含缺陷代码。请重新完整编译后再运行，确保运行的 exe 是由当前源码生成的。

## 使用注意事项

- 编译命令必须带 `-std=c++17`。
- 所有 `.h` 和 `.cpp` 文件必须放在同一目录，才能使用 `*.cpp` 通配编译。
- 不要修改或重命名源文件，否则需要按文件清单单独编译。
- 本程序是演示程序，运行结束后会自动关闭并退出，没有交互操作。

## 项目功能范围

当前程序支持：

- 多发布者和多订阅者使用同一个 Topic 通信。
- 不同 Topic 之间的消息隔离。
- 消息队列和独立工作线程的异步消息处理。
- 节点初始化、注册、注销和统一关闭。
- 空消息、空节点名称、重复节点名称、未初始化发布等异常的检测。

当前程序不支持（也不属于本项目目标）：

- 真实 ROS 节点通信。
- 不同计算机之间的网络通信。
- 图形化界面。
- Service、Client 等其他 ROS 通信机制。
